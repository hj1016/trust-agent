# TASK-030 승인 근거 AI 답변과 기록 분리 반영

- 상태: 구현 반영과 로컬 자동 검증 통과. 사용자 검수와 Explainability Gate 대기.
- 담당: AI는 기존 코드 선별과 통합, 자동 검증, self-review, 커밋과 PR 생성. 사용자는 근거와 결과 대조, 설계 이해 확인과 수동 병합.
- 요구 출처: 사용자가 기존 AI 답변 생성과 기록 작업을 최신 main에 연결해 검증하고 PR을 만들도록 지시했다. UI 변경과 비밀값, 불필요한 생성 파일은 제외한다.
- 기준선: main 0492490(PR #55, #56 포함). ADR-011의 읽기 Tool 경계, ADR-012의 기록 전 재확인, ADR-013의 검색 경계를 유지한다.

## 목표와 범위

담당 행원이 상담 건에서 규정 질문을 보내면 승인 근거 검색, 설명 생성과 검증, Core 재확인, 답변 요청 이력 기록까지 연결한다. 기존 로컬 구현을 선별하며 이번 통과를 실제 모델 품질 평가 완료로 표현하지 않는다.

포함: Core 추가 질문 API, AI 답변 API, 생성 및 추가 검증, 문장별 인용과 숫자/날짜/상품 범위 검사, Bedrock 호출 예산 통제와 로컬 Ollama 연결, V13 답변 요청 감사 기록, 관련 테스트와 설명.
제외: UI 변경, 모델 가중치와 유료 호출, 새 예산 승인, 원본 실행 로그와 캡처, 공문 열람/변경 비교 API, 상담 재개 및 V14 이후 migration, 공통 검색 프로필과 모델/검색 품질 비교. 변경 비교 자료가 없는 질문에는 과거 규정을 추측하지 않는다.

완료 기준 변경 없음. 계획: 최신 main에서 별도 브랜치를 만들고 필요한 코드만 선별한다. Java는 V13 단계의 컨트롤러/설정/DB 검증 변경을 사용하고, Python은 기존 최신 답변 검사 모듈을 사용하되 검색 프로필과 이후 업무 기능은 끌어오지 않는다. 컴파일과 테스트에서 발견된 연결 문제는 이 범위 안에서 수정하고 기록한다.

## AI 제안 및 인간 판단 기록

- 제안: 원본 브랜치를 통째로 병합하지 않고 승인 근거 답변과 기록을 별도 PR로 선별한다. 원본 브랜치와 과거 evidence는 유지한다.
- 대안과 이유: 전체 병합은 UI와 별도 상담 기능, 대량 생성 자료를 포함해 사용자 제외 범위와 충돌한다. 선택한 방식은 통합 검증 부담이 있지만 PR 범위를 읽고 검토할 수 있다.
- 인간 판단: 사용자가 위 분리/검증/PR 생성 순서에 “진행해줘”라고 지시했다. 이는 실행 승인이고 결과물 검수 완료가 아니다.
- 위험과 대응: 최신 Python 검사와 이전 Core 기능 사이 계약 차이는 단위/연결 테스트로 확인한다. 동일 모델의 생성과 검증은 같은 오류를 놓칠 수 있으므로 코드 검사와 직원 원문 확인을 유지한다.
- 트랜잭션: 모델/HTTP 호출 중 DB 트랜잭션을 유지하지 않는다. 감사 기록은 결과 제공 전에 저장하며 저장 실패를 성공으로 표현하지 않는다.
- 사용자 검토 범위: 대표 입력과 근거/응답 대조, 보류 이유, 역할 경계와 선택 이유 설명, 실제 모델 검증 미완료 인지.

## 구현 결과와 자동 검증

기존 코드 선별, 답변 API 연결, V13 요청 이력, 관련 검사와 문서를 반영했다. 운영 평가 기록 차단을 함께 반영했고, 빈 근거/인용 및 깨진 답변 형식은 Core에서 보류하도록 보완했다. Python 233건(228 통과, skip 5), Java 전체 260건(257 통과, skip 3), 최종 답변 연결 8건 모두 통과했다. 대상 revision, 실행 명령, 환경, 실패/skip과 결과는 docs/evidence/APPROVED_EVIDENCE_ANSWERS_INTEGRATION.md에 기록한다.

## AI self-review와 인간 검수

AI self-review에서 기동 검사 누락과 빈 근거의 성공 응답을 발견해 보완하고 관련 검사를 통과했다. UI/CI 변경 없음과 문서의 현재 상태를 확인했다. 비용이 발생하는 실제 모델 호출은 하지 않았고 모델 품질 평가와 변경 이력 비교 기능은 남아 있다. 사용자 검수와 Explainability Gate 대기. 자동 테스트는 업무 규칙에 대한 인간 판단과 실제 모델 품질 검토를 대신하지 않는다.
