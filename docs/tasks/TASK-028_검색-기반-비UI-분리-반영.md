# TASK-028 승인 근거 검색 기반의 비UI 분리 반영

- 상태: 구현 반영 및 자동 검증 통과. 인간 검수와 Explainability Gate 대기.
- 담당: AI는 기존 코드 선별, 통합, 자동 검증, 커밋과 PR 생성. 사용자는 업무 판단, 검수와 수동 병합.
- 출처: 사용자의 기존 작업 커밋 및 PR 분리 요청. UI 변경, 비밀값, 불필요한 생성 파일 제외. 기존 TASK-016 검색 기준선과 후속 하이브리드 구현을 재사용한다.

## 목표와 범위

최신 원격 main에서 승인 근거 검색 API와 BM25, vector, RRF hybrid의 실행 기반을 독립적으로 검토할 수 있게 한다. 새 검색 모델 선택이나 검색 품질 완료를 선언하는 작업이 아니다.

포함: 검색 API와 계약, 수신 토큰 및 grant 전달, 검색 전 Core 승인 및 권한 확인, 검색 결과의 근거 재확인, 로컬 e5 임베딩 인터페이스와 벡터 색인, nori 검증 이미지, 검색 평가 도구와 테스트.
제외: 프런트엔드와 화면 전용 하네스 변경, LLM 답변, 상담 업무 migration, 모델 가중치, 원본 snapshot, 대량 실행 로그 및 코드 사본. 공통 JSON 검색 프로필과 이후 검색 조정 로직은 후속 반영한다.

## 대안과 판단

- 기존 feat/ai-eval-final 전체 push: UI와 별도 상담 기능, 생성 기록이 섞여 사용자 제외 범위를 지키기 어려워 채택하지 않는다.
- 기존 검색 Draft PR #50 전체 병합: 초기 검색 코드와 대량 과거 평가 자료가 함께 있어 새 분리 PR에서 필요한 코드와 테스트만 선별한다. 기존 브랜치와 기록은 수정하거나 삭제하지 않는다.
- 채택 범위: origin/main ac62801에서 기존 검색 커밋 0bd0bfd, 00e68f2, fce03d2, ceed2b3, e334d04의 관련 파일을 선별. 원본을 보존하고 분리한 최종 상태를 새 커밋으로 남긴다.
- 판단 출처: 사용자가 비UI 작업 커밋 및 PR 생성을 승인하고 병합은 직접 수행하도록 지시. 이 실행 승인은 기능 검수 통과를 뜻하지 않는다.

## 선택과 트레이드오프

- 승인 근거의 최종 판단은 Core가 수행한다. 재확인 호출이 늘지만 검색 점수나 오래된 색인으로 사용 허용을 확정하지 않는다.
- 기본 검색 모드는 기존 동작인 BM25를 유지하며 vector 및 hybrid는 명시 설정으로 실행한다. 임베딩은 기존 e5-small 인터페이스를 보존한다. BGE-M3 비교와 임계값 확정은 다음 작업이다.
- 원본 역사적 기록은 기존 브랜치에 보존한다. 새 PR은 재현 코드, 테스트, 최소 실행 요약만 포함하며 과거 결과를 새 코드의 성능으로 옮기지 않는다.
