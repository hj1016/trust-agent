# TASK-029 PR 문체와 작업 관례 기록

- 상태: 문서 반영 및 자체 검토 완료. 사용자 검수 대기.
- 담당: AI는 기존 관례 확인과 문서 수정, 사용자는 검수와 수동 병합.
- 출처: 사용자의 브랜치명 수정, 관례 발견 시 알림과 MD 갱신 지시, 명사형 강제 대신 기존 평서형 문체 유지 지시.
- 관련: PR #53의 설명 문장과 변경 목록, PR #55의 문체 정리. 구현 변경과 독립된 문서 PR이다.

## 목표와 범위

PR 설명 문체, 작업 목적 중심 브랜치명, 관례 발견 시 보고와 문서 반영 기준을 DEVELOPMENT_RULES.md에 기록한다. AGENTS.md와 CLAUDE.md의 기존 개발 규칙 참조를 유지해 기준을 중복하지 않는다. 코드, UI, 과거 PR과 Git 이력, 별도 skill은 변경하지 않는다.

## 사전 확인 기준과 계획

| ID | 확인 기준 | 검증 방법 |
|---|---|---|
| AC-01 | 평서형 설명과 간결한 목록을 허용하고 명사형을 강제하지 않음 | 사용자 최신 지시와 문서 대조 |
| AC-02 | 기능 중심 브랜치명과 AI 도구 접두사 제외 명시 | 브랜치 예시 및 규칙 검토 |
| AC-03 | 관례의 근거와 범위를 알리고 기준 MD 갱신 | 관찰과 명시 규칙의 구분 확인 |
| AC-04 | 문서만 변경하고 기준 중복과 skill 신설 없음 | diff와 기존 참조 확인 |

개발 규칙에 필요한 항목만 추가하고 diff, 공백 오류, 비밀 탐지를 확인한 뒤 독립 커밋과 PR을 만든다. 문서 변경이므로 애플리케이션 테스트는 새로 실행하지 않는다.

## AI 제안 및 인간 판단 기록

- AI 제안: PR 문체를 명사형으로 통일하는 방향을 제시했다.
- 인간 판단: 사용자가 명사형 지시를 정정하고 `했다, 무엇무엇이다` 등 기존 관례를 따르도록 지시했다.
- 반영: 명사형 통일안을 폐기하고 설명은 평서형, 목록은 간결한 표현을 허용했다. 이는 문서 수정 실행 지시이며 결과물 검수 통과를 의미하지 않는다.
- 대안: 별도 skill에 규칙을 복제할 수 있으나 저장소 공통 규칙이므로 기존 개발 규칙에 통합했다. 반복 실행 절차의 skill 분리는 향후 필요할 때 검토한다.

## 검증과 AI self-review

사용자 정정과 PR #53 문체에 대조해 AC-01~03을 확인했다. AGENTS.md와 CLAUDE.md는 이미 DEVELOPMENT_RULES.md를 참조해 별도 복사 없이 AC-04를 충족했다. 최종 diff와 비밀 검사는 커밋 및 PR에서 확인한다. 적용 범위를 새 작업과 PR 작성에 한정해 과거 이력을 소급 수정하지 않는다.

## 인간 검수와 완료

사용자 검수 대기. 문서 수정과 자동 검증 결과는 인간 검수 및 Explainability Gate 통과를 대신하지 않는다. 병합은 사용자가 수행한다.
