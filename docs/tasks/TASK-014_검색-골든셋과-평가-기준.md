## Goal / 관련 요구사항

- Goal: 검색을 구현하기 전에 "무엇을 찾아야 정답이고, 무엇이 나오면 안 되며, 언제 보류해야 하는가"를 데이터와 숫자로 고정한다. 이후 TASK-016(BM25)과 TASK-018(벡터 + reranker)은 같은 골든셋으로 비교한다.
- 입력: 합성 공문 4건(중도상환수수료 v1·v2, 셀러론 v1·v2)의 규칙 version ID(아래 표), TASK-007·008로 확정된 "사용 가능" 상태 규칙(승인된 중도상환수수료 v2 항목 3개), 합성 신청 건.
- 출력: 골든셋 파일 2개, 골든셋 계약 schema, 지표 정의와 계산 방법, 평가 스크립트 명세, 통과 기준 확정 기록. **코드 변경 없음**(평가 스크립트 구현은 TASK-016).
- 사용자: 검색 구현자(AI)와 판정자(사용자). 골든셋은 행원 질문을 흉내 낸 합성 질의이며 실제 상담 기록이 아니다.
- 데이터 분류: 골든셋은 `SYNTHETIC_WORK`(가상 질문)로 표시하고 정답 ID는 `SYNTHETIC_INTERNAL` 규칙 version을 가리킨다.
- Out of Scope: 검색 구현, 색인, 임베딩 모델 선택, 실제 행원 질문 수집.

## 골든셋 구조

- 파일: `datasets/synthetic/search-goldenset/prepayment-fee-smoke-v1.json`(초기 점검용 10건), `datasets/synthetic/search-goldenset/prepayment-fee-eval-v1.json`(최종 평가용 20~30건). 계약 `contracts/search-goldenset.schema.json`.
- 질의 항목: `query_id`, `query`(행원 질문), `family_id`, `business_date`, `relevant`(규칙 version ID 목록, 순서 무관), `must_not`(규칙 version ID 목록), `expected_hold`(true면 "사용 가능한 근거 없음 → 보류"가 정답), `category`(아래), `rationale`(왜 이 정답인지 한 줄). 파일 머리에 `dataset_class: SYNTHETIC_WORK`, `synthetic: true`, 면책 문구, `goldenset_version`.

## 지표와 계산 방법 (제안, 확인 뒤 확정)

평가 대상은 "검색 후보 → Core Tool 2 재확인 → 통과한 근거 목록(순위 유지)"이다. 재확인 전 후보가 아니라 **재확인 뒤 목록**으로 계산한다.

| 지표 | 계산 | 제안 기준(기준선 BM25 / 최종) |
|---|---|---|
| Recall@5 | 질의별 `relevant` 중 상위 5개 안에 든 비율의 평균(`expected_hold=true`인 질의는 제외) | ≥ 0.8 / ≥ 0.9 |
| MRR | 질의별 첫 `relevant`의 순위 역수 평균(없으면 0, hold 질의 제외) | ≥ 0.7 / ≥ 0.8 |
| 노출률 | 모든 질의에서 `must_not`이 재확인 뒤 목록에 나온 건수 | **0건(필수, 두 단계 공통)** |
| 보류 정확도 | `expected_hold=true` 질의 중 재확인 뒤 목록이 비어 "보류"가 된 비율 | 100% |
| 잘못된 보류 | `expected_hold=false`인데 목록이 빈 비율 | ≤ 10% / ≤ 5% |
| Core 재확인 호출 수 | 질의당 Tool 2 호출 수(후보 수) | 기록만 |

- 수치 확정 절차: 골든셋 초안(질문, 정답 근거, 보류 사례)과 위 계산 방법을 사용자가 확인한 뒤 기준값을 확정하고 이 문서의 "판단 기록"에 남긴다. 확정 전에는 제안값이다.
- 재확인이 거부한 후보는 지표 계산에서 "없던 것"으로 본다(검색 품질이 좋아도 Core가 막으면 결과가 아니다).

## 평가 스크립트 명세 (구현은 TASK-016)

- 입력: 골든셋 파일 경로, 검색 API 주소, Tool 토큰(환경변수), 평가 시각(테스트 시계와 같은 고정값).
- 동작: 질의마다 검색 API 호출 → 후보별 Tool 2 호출 → 통과 목록 → 지표 계산 → 결과 파일 `docs/evidence/SEARCH_EVALUATION_<구성>_<골든셋 버전>.md`(질의별 상위 5개와 통과 여부, 지표 표, 실패 질의 목록).
- 같은 골든셋 버전으로 BM25 기준선과 최종 구성을 각각 실행해 비교표를 만든다. 골든셋을 고치면 버전을 올리고 두 구성을 다시 돌린다.
