# ADR 011 Core Tool API 접근 범위와 서비스 인증

## 상태

승인 (접근 범위와 test/demo 인증 방향. 결정자 사용자, PR #28)

## 배경

CLAUDE.md는 AI Service(Python + FastAPI)가 업무 DB에 직접 접근하거나 업무 DB 자격증명을 갖는 것을 금지하고, Core Tool API를 통해 필요한 업무 데이터만 조회하도록 정한다. TASK-005~007, 013으로 Core에는 변경안 생성, 자동 검증, 사람 검토 결정, 승인 checklist 발행과 적용 공문 조회가 갖춰졌다. 이제 AI 서비스가 읽을 수 있는 경계를 정해야 한다. 경계가 느슨하면 미승인 변경안이나 철회된 공문의 원문이 AI 답변에 섞이고, 사람 승인 전 기준이 행원에게 전달될 수 있다.

## 결정

### 접근 범위

1. **읽기 전용 Tool만 둔다.** AI 서비스용 진입점은 `POST /api/v1/tools/{toolName}` 하나이고, allowlist는 코드 상수 두 개(`applicable_checklist`, `rule_evidence`)다. 승인, 수정, 반려, 변경안 생성, 검증 실행 같은 쓰기 Tool은 만들지 않는다. allowlist 밖 이름은 404다.
2. **사용 허용 여부는 Core가 결정한다.** `internalChecklistUseAllowed`와 차단·경고 사유는 기존 적용 공문 조회 서비스(`InternalChecklistUsePolicy`)의 결과를 쓰고, AI가 재계산할 수 있는 정책 입력 플래그는 응답에 넣지 않는다. AI가 응답을 어떻게 해석하더라도 서버의 차단을 바꾸거나 우회할 수 없다. 사용 불가 상태에서는 내용 자체가 전달되지 않고, 근거 요청은 서버가 다시 확인하며, 요청 본문의 값은 차단 판단에 영향을 주지 않는다.
3. **사용 가능할 때만 내용을 준다.** `usable=false`면 사유만 주고 checklist 항목과 항목 근거 ID(규칙 version)는 null이다. 미승인 변경안, 검증 결과, 검수자 ID, 변경안 ID, 결정 사유는 어떤 경우에도 Tool 응답에 없다. 승인된 checklist의 출처(`HUMAN_REVIEW`)와 결정 ID는 준다.
4. **근거는 소속과 상태를 서버가 다시 확인한 뒤 준다.** `rule_evidence`는 요청한 공문군의 현재 사용 가능한 승인 checklist 항목이 가리키는 규칙 version일 때만 원문 문장과 위치를 돌려준다. 다른 공문군의 규칙, 미승인·반려·FIXTURE 항목의 규칙, 사용 불가 상태(철회, 선택 변경·모호, 필수 공개 근거 미확인 포함)는 403이다. 공문 본문 전체는 어떤 Tool로도 나가지 않는다.
5. **조회는 항상 현재 시각 기준이다.** 과거 기준 시각(`knownAt`) 입력은 schema에 없고 보내면 400이다. 과거 기록 재현은 사람용 조회 API의 역할이다.
6. **요청 본문의 문장은 데이터다.** 지시문처럼 보여도 명령으로 해석하지 않으며, schema 밖 필드는 400이다.
7. **기록 없는 제공은 없다.** 모든 Tool 호출은 감사 로그(`tool_call_audit`, append-only, 보호 목록)에 서비스 ID, tool 이름, 공문군·업무일·상담 ID, 결과 코드와 사유, 시각을 남긴다. 저장에 실패하면 응답도 실패한다. 본문, 규칙 원문, 토큰은 기록하지 않는다.

### 서비스 인증

8. **test/demo 범위의 공유 비밀 토큰 1개.** 환경변수 `TRUST_AGENT_TOOL_SERVICE_TOKEN`으로만 제공한다. 실제 자격증명은 저장소 파일, 예시 설정, 테스트 코드, 로그에 남기지 않는다. 인증 테스트는 실행 중 생성한 임시 토큰을 쓴다. 토큰에 묶인 서비스 ID(`ai-service`)만 감사 로그에 기록하고 호출자가 보낸 actor 문자열은 쓰지 않는다.
9. **누락은 허용이 아니다.** 토큰 설정이 없는 환경에서는 올바른 토큰이 와도 모든 Tool 호출이 401이다. production profile은 설정이 없으면 기동을 거부한다.
10. **상담 ID는 추적용이다.** 접근 권한을 주지 않고 응답 내용에도 영향을 주지 않는다.
11. **사용자별 인증·권한은 미구현이다.** 행원 개인의 신원, 역할, 담당 범위 검사와 조직 인증 체계 연동은 이 ADR의 범위 밖이며 후속 ADR로 다룬다. 이 결정은 "AI 서비스라는 하나의 호출자"를 구분하는 수준이다.

## 근거

- DEVELOPMENT_RULES: Tool allowlist, 입력/출력 schema, 최소 데이터, 감사 추적, 미승인·철회·구버전·권한 밖 근거 제외, fail-closed.
- ADR-003: 자동 검증과 사람 승인의 구분. 승인되지 않은 것은 업무 기준이 아니다.
- ADR-007: 응답에 내부 경로, 원문 HTML, 인증 정보를 넣지 않는다.
- 대안 검토: (a) 항목은 주되 `usable=false`만 표시 → AI가 실수로 쓸 위험이 있어 거절. (b) 서비스별 토큰 여러 개 → 현재 호출자는 하나이고 조직 인증 연동 전이라 보류. (c) 근거 읽기는 허용하되 상태 표시 → 미승인 원문이 AI에 나가므로 거절.

## 결과

- AI 서비스는 Core를 통해서만, 승인되고 지금 사용 가능한 기준만 읽는다.
- 사람 승인 전 기준과 근거는 AI 답변에 들어갈 수 없다.
- 운영 전환 시 토큰 인증을 조직 인증 체계로 바꾸고 사용자별 권한을 추가해야 한다(후속 ADR).
