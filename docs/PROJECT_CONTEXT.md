# TrustAgent 프로젝트 기준

## 목표

1인 최종 프로젝트로 시연 가능한 TrustAgent MVP를 2주 안에 완성합니다.

## 제품 경계

TrustAgent는 은행 기업여신 담당자의 상담과 심사 준비를 지원합니다. 대출 판단은 수행하지 않습니다. KB 공개 상품 fact와 합성 내부업무 데이터는 저장소, schema, API, 화면, 테스트, 평가 결과에서 동일한 기준으로 구분합니다.

## MVP 집중 범위

- KB 공개 상품 3개의 baseline snapshot과 manifest
- KB 셀러론 중심의 E2E 흐름
- v1과 v2로 구성된 합성 내부 공문 한 계열
- 합성 기업과 신청 각 1건
- 기준일 검색, 자동 검증, 별도의 사람 승인
- 전체 흐름을 연결하는 evidence와 audit ID

## 대표 데모

1. KB 셀러론 snapshot과 정규화된 fact를 조회합니다.
2. source URL, 수집시각, 기준일, source locator와 hash를 확인합니다.
3. 합성 내부 공문이 공개 fact를 참조합니다.
4. 공문 v1과 v2를 비교해 체크리스트 변경 후보를 만듭니다.
5. 법인 한도를 2억원으로 잘못 작성한 결과를 차단합니다.
6. 원문 fact의 20억원으로 수정하고 사람 승인을 기록합니다.
7. 합성 시행일 전후에 맞는 체크리스트를 각각 검색합니다.
8. 합성 기업과 신청 건의 상담 준비안을 생성합니다.
9. 행원이 근거를 확인하고 최종 승인합니다.
10. 수집부터 승인까지 audit trace를 재생합니다.
11. AI 서비스를 중단하고 수기 준비는 가능하지만 AI 확정은 차단되는지 확인합니다.

## 데이터 분류

- `PUBLIC_KB`: KB 공식 공개 상품 페이지와 불변 snapshot
- `SYNTHETIC_INTERNAL`: 프로젝트용 합성 내부 공문, 규정, 코드, 체크리스트
- `SYNTHETIC_WORK`: 프로젝트용 합성 기업, 여신, 신청, 상담, 승인
- `DERIVED`: 원천 ID를 보존한 diff, 영향 후보, embedding, 자동 검증 결과, AI 결과

## 완료 정의

- 공개 snapshot부터 최종 사람 승인까지 대표 데모가 동작합니다.
- 중대 자동 검증 실패가 화면과 API 승인 경로를 모두 차단합니다.
- 요청 기준일이 구버전, 미래버전, 중첩 버전을 제외합니다.
- 공개 데이터와 합성 데이터가 허용된 경계를 넘지 못합니다.
- 인수 테스트가 반복 가능한 evidence를 생성합니다.
- README, ADR, API와 ERD, Runbook, 평가 결과, 발표 자료가 실제 구현 상태와 일치합니다.
