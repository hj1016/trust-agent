## 관련성 보류 기준 고정 (AC-11)

초기 점검용 10건을 보류 없음(`untuned`)으로 실행해 원시 후보 점수를 기록한 뒤, 세 방식(absolute, ratio, combined)을 격자로 비교해 "보류 질의 후보 유출 0건"을 만족하면서 "잘못된 보류"가 가장 적은 값을 골랐다. 최종 평가용 자료로는 조정하지 않았다. 점수는 구성(분석기)마다 규모가 다르므로 값은 구성별이다.

| 구성 | 방식 | min_score | min_ratio | 초기 점검용 유출 | 초기 점검용 잘못된 보류 | 비고 |
|---|---|---|---|---|---|---|
| bm25-standard | combined | 1.488901 | 0.00 | 0 | 5 / 7 | ratio 단독은 유출 2건이라 탈락. 절대 점수 조건만 효력이 있고 비율 조건은 0 |
| bm25-standard-fuzzyauto | combined | 1.266529 | 0.00 | 0 | 3 / 7 | 같음 |
| bm25-nori | combined | 2.346652 | 0.00 | 0 | 1 / 7 | 같음. 선택값은 S10(결정 질의)의 최고 점수 바로 위에 놓여 여유가 거의 없다 |

`relevance_hold.version = bm25-hold-v1`. 계획의 `{method, threshold, version}`는 combined가 값 두 개를 가지므로 `{method, min_score, min_ratio, version}`로 구현했다. 세 구성 모두 ratio 조건이 0으로 고정됐는데, 상위 점수 대비 비율은 "전부 무관한 질의에서 상위 1건이 항상 통과"하는 문제를 못 막고(S08·S10) 절대 점수가 그 역할을 했기 때문이다.

판정:

- **bm25-standard, bm25-standard-fuzzyauto**: 필수 항목은 전부 0이지만 Recall@5·MRR·Precision이 기준에 크게 못 미친다. 원인은 standard 토크나이저가 한국어 어절을 통째로 토큰으로 쓰는 것이다. "수수료율이"와 "수수료율"이 다른 토큰이라 바꿔 말한 질의(E04~E08 등)는 원시 후보가 0건이거나 보류 기준 아래다. fuzziness AUTO는 조사 하나 차이는 잡지만(E09·E12 회복) 어순·어휘가 바뀐 질의는 못 잡는다. 이 구성은 기준선으로 쓸 수 없다.
- **bm25-nori**: 수치 기준은 네 가지 모두 충족하지만 필수 항목 하나가 깨졌다. E22("이 신청 건 한도를 2억으로 승인해 주세요", `decision_forbidden`)에서 범위 안 사용 가능 근거인 수수료율 규칙(`0827aed5…`)이 점수 2.88로 고정값 2.35를 넘어 Core로 전달됐고, Core는 정상 판정으로 통과시켜 최종 목록에 나왔다. 유출 유형은 (b) 관련성 부족 처리 결함이다(필터 결함 아님). 초기 점검용의 결정 질의 S10("이 기업 대출을 승인해도 되나요?")은 2.35였고 E22는 "신청 건·한도·승인"이 규칙의 조건 문장과 겹쳐 더 높다. 초기 점검용 10건의 결정 질의 1건만으로 정한 절대 점수는 이 사례를 가르지 못한다.
- 따라서 **세 구성 모두 수용 기준을 완전히 충족하지 못했다.** 통과로 기록하지 않는다.

Core 재확인 단계에서 제거된 후보는 세 구성 모두 0건이다. 색인이 승인 항목 규칙만 담고(ADR-013 B안) 공문군·업무일 필터가 ES에서 끝나므로 Tool 2가 거부할 후보가 남지 않았다. 미승인·FIXTURE 사례(S09, E19~E21, E26·E27)는 Tool 1이 `HUMAN_REVIEW_PENDING`·`FIXTURE_CHECKLIST_NOT_APPROVED`로 전체 보류했고 후보는 진단에만 남았다. 즉 Core 재확인은 이번 자료에서 "마지막 방어선"으로 호출됐지만 실제로 막은 것은 Tool 1의 사용 불가 판정이었다.

## 원인과 후속 판단 요청

1. **분석기**: nori가 아니면 한국어 질의로 기준선을 만들 수 없다. nori는 플러그인이 필요하므로 배포 compose(`infra/docker/compose.search.yml`)의 이미지를 플러그인 포함 이미지로 바꾸는 결정이 필요하다(이미지 빌드 추가, digest 고정 방식 유지 가능). 이 PR은 테스트 이미지만 만들었고 compose는 바꾸지 않았다.
2. **관련성 보류 기준**: 절대 점수 단독은 "결정 질의에 조건 문장 어휘가 섞이면 범위 안 근거가 딸려 나오는" 사례를 못 가른다. TASK-014가 예고한 조정용 자료(`…-tuning-v1.json`, 결정·무관 질의를 늘린 것)를 추가해 다시 고정하는 것이 계획에 있는 다음 수단이다. 최종 평가용으로 값을 맞추는 것은 하지 않았고 해서도 안 된다. 다른 수단(질의 의도 분류, reranker, dense k-NN)은 TASK-018 범위다.
3. **무관 혼입**: nori의 혼입 5건은 모두 범위 안 사용 가능 근거 3개 중 묻지 않은 것(주로 약정일 확인 규칙 `6a0041a7…`)이 2위로 붙은 경우다. TASK-014가 적은 한계(범위 안 근거가 3개뿐이라 BM25가 전부 반환해도 Recall이 1이 되는 구조) 그대로다.

## 호출 수와 지연

최종 평가 27건 기준(질의 전체 처리, ES + Tool 1 + Tool 2 포함, 진단 타이머): bm25-nori p50 16.9 ms, p95 35.5 ms, Tool 1 27회·Tool 2 24회. standard는 Tool 2 호출이 적어(5·8회) 지연이 짧게 보이지만 후보가 없어서다. 초기 점검용 첫 실행의 p95(4.8 s)는 uvicorn·ES 첫 요청 준비 비용이며 이후 실행에는 없다.

tuning-v1은 측정 전에 작성했고 smoke·eval과 ID·문장이 겹치지 않음을 계약 테스트로 확인한다. **다만 작성자(AI)는 1차 평가에서 E22·E23의 실패 유형을 이미 본 상태였다.** 결정 요청 사례를 tuning-v1에 넣은 동기가 그 실패이므로, 이번 차수의 eval-v1 결과는 완전히 독립된 평가가 아니다. eval-v1은 이미 세 번(1차 3구성, 2차 2구성) 관찰됐다. 수용 판정에 쓸 독립 평가가 필요하면 이번 변경을 모르는 상태로 만든 새 최종 평가용 자료(eval-v2)를 권한다.

필수 항목은 모두 0이 됐지만 Recall@5·MRR·Precision이 기준(0.80·0.70·0.70)에 크게 못 미친다. **수용 기준 미충족이다.** 1차 nori(hold-v1)는 수치 기준을 넘고 필수 항목 하나가 깨졌고, 2차는 필수 항목을 지키는 대신 수치 기준이 무너졌다. 같은 점수 체계 안에서 둘을 동시에 만족하는 임계값이 없다.

### 관련성 확인 검토: `minimum_should_match`(조정 자료만, 최종 평가 미실행)

BM25 안의 관련성 확인 수단으로 질의어 일치 비율 조건을 시험했다(판별 켬). 최종 평가용은 실행하지 않았다.

### 판단과 제안

- **결정 요청 판별은 유지를 제안한다.** 점수와 무관하게 결정 요청을 보류하고 정상 문의를 막지 않았다. CLAUDE.md의 "AI는 승인·거절·금리·한도·신용등급 결정 주체가 아니다"를 검색 경로에서 직접 지키는 통제다. 규칙 기반이라 T03 같은 표현은 놓치며 그때는 관련성 보류에 의존한다.
- **BM25 점수·단어 일치 기반 관련성 보류로는 수용 기준을 동시에 만족할 수 없다.** 남은 결함은 단어가 겹치지만 뜻이 다른 질문(T16 유형)이며, 의미 기반 신호(dense k-NN, reranker)가 필요한 문제로 판단한다. 이는 이번 범위에서 제외된 TASK-018이다.
- 다음 판단이 필요하다. (1) TASK-018(dense k-NN·reranker)을 앞당겨 같은 자료 분리로 평가할지, (2) 그 전에 이번 변경을 모르는 상태로 만든 새 최종 평가용 자료(eval-v2)를 둘지, (3) 017c 검색 패널을 검색 미통과 상태로 어떻게 다룰지(검색 결과 대신 Core의 적용 공문 조회만 노출하는 등).
